# 怪物战力筛选页签设计

## 概要

在现有洛奇战斗力计算器中增加一个“怪物筛选”页签。用户可以基于当前角色总战斗力，筛选出 Weakest、Weak、同级、Strong、Awful、Boss 各档位的怪物。页面默认显示 G13 及以前、非活动、有有效 CP 的怪物；仓库保留完整已知怪物 CP 数据，供后续补译名、补版本和切换完整数据范围使用。

战力、战斗力、强度值、Combat Power 和 CP 在本文中表示同一概念。

## 目标

- 在现有静态网页中增加页签式怪物筛选能力。
- 默认使用当前选中角色的总战斗力，并支持手动覆盖战力。
- 按怪物 CP 与角色 CP 的倍率关系计算相对强度。
- 默认只显示 G13 及以前的常规怪物。
- 在仓库中保存尽量完整的怪物 CP 表。
- 能找到简体或繁体译名的怪物尽量补全中文译名。
- 保留英文原名作为核对和搜索依据。

## 非目标

- 不把怪物筛选页做成完整怪物图鉴。
- 不在第一版结果表展示血量、伤害、防御、保护、经验或金币。
- 不引入后端、数据库、npm 构建步骤或在线查询。
- 不要求第一版完成所有怪物译名的人工校对。
- 不让手动覆盖战力反写角色档案。

## 应用形态

应用仍是本地静态网页。新增 UI 与数据都通过普通脚本文件加载，不引入构建工具。页面顶部增加轻量页签：

- `角色战力`：保留现有角色档案、白值、技能、计算结果、导入导出。
- `怪物筛选`：展示战力输入、筛选条件、强度区间和怪物结果表。

页签状态属于界面状态，不写入角色导出 JSON。切换页签不应丢失当前角色编辑内容。

## 数据来源与数据边界

主要怪物 CP 来源为 Mabinogi World Wiki 的 `List of Monster CP`。日文 Mabinogi Wiki 的 CP 与敌人等级说明可用于核对倍率规则和版本线索。国服官网、繁中资料或其他可靠页面可用于补充中文译名。

数据分两层维护：

- 原始数据层：仓库保存从来源整理出的完整已知怪物 CP 数据，尽量保留英文名、CP、地点、来源 URL、来源备注和未用于页面展示的原始字段。
- 运行数据层：网页加载精简怪物记录，只保留筛选需要的字段。

运行数据字段：

- `id`：稳定内部标识。
- `zhCNName`：大陆简体译名。缺失时可回退显示英文名。
- `zhTWName`：繁中译名，用于搜索和校对。
- `enName`：英文原名。
- `combatPower`：怪物 CP 数值。
- `locations`：地点或来源场景列表。
- `introducedBy`：能确认时标注 `G1` 到 `G13` 等版本；不能确认时标注 `unknown`。
- `isEvent`：是否为活动或临时记录。
- `translationStatus`：`confirmed`、`autoConverted` 或 `missing`。
- `source`：来源标识或 URL。

默认页面范围为 G13 及以前、非活动、有有效 CP、版本可确认的怪物。完整数据仍保存在仓库，并可在网页中通过范围筛选切换到“全部已知数据”。

## 译名策略

英文名始终保留，用作稳定核对依据。中文译名分状态维护：

- `confirmed`：来自国服官网、已有可靠中文资料，或经人工确认。
- `autoConverted`：只有繁中译名，简体名由繁转简得到，尚未人工确认。
- `missing`：没有可靠中文译名，简体显示回退为英文名。

搜索需要同时匹配简体名、繁中名和英文名，避免译名不完整时找不到怪物。

## 版本与特殊记录策略

默认筛选应尽量服务 G13 及以前玩法：

- 明确为 G13 之后的怪物，不在默认范围显示。
- 明确为活动或临时事件的怪物，不在默认范围显示。
- 缺少 CP 的记录不参与筛选，但保留在原始数据中。
- 版本未知的记录标为 `unknown`，默认不显示。
- 筛选器提供“包含版本未知”开关，方便用户在需要时扩大结果。
- 切换到“全部已知数据”时，页面提示数据包含后期、版本未知或译名未校对记录。

## 强度分档

怪物强度由下式计算：

```text
相对强度倍率 = 怪物 CP / 当前使用的角色 CP
```

当前使用的角色 CP 默认来自当前选中角色的总战斗力。如果用户填写手动覆盖战力，则使用覆盖值。覆盖值只影响怪物筛选，不保存进角色档案。

分档规则：

- `Weakest / 非常弱的敌人`：倍率小于 `0.8`。
- `Weak / 弱的敌人`：倍率大于等于 `0.8` 且小于 `1`。
- `同级敌人 / 无标示`：倍率大于等于 `1` 且小于 `1.4`。
- `Strong / 强敌`：倍率大于等于 `1.4` 且小于 `2`。
- `Awful / 非常强悍的敌人`：倍率大于等于 `2` 且小于 `3`。
- `Boss / 首领级的敌人`：倍率大于等于 `3`。

区间边界采用左闭右开，最后一档为大于等于 `3`。页面应显示各档位对应的怪物 CP 数值区间，帮助用户理解筛选结果。

## 筛选功能

怪物筛选页签包含以下条件：

- 当前使用战力：显示来自当前角色或手动覆盖。
- 手动覆盖战力：大于 `0` 的数字。
- 强度多选：Weakest、Weak、同级、Strong、Awful、Boss。
- 名称搜索：匹配简体名、繁中名、英文名。
- 地点搜索：匹配地点或来源场景。
- 数据范围：默认 `G13 及以前`，可选 `全部已知数据`。
- 包含版本未知：默认关闭。
- 译名状态：全部、已确认、自动转换、待翻译。

结果默认按 CP 从低到高排序，方便找到当前档位中更接近下限的怪物。

## 用户界面

`怪物筛选` 页签采用左右结构。

左侧为筛选条件：

- 当前使用战力摘要。
- 手动覆盖战力输入框。
- 强度多选按钮。
- 名称搜索框。
- 地点搜索框。
- 数据范围切换。
- 包含版本未知开关。
- 译名状态筛选。

右侧为结果区：

- 当前战力下的 Weakest、Weak、同级、Strong、Awful、Boss CP 区间。
- 结果数量和过滤摘要。
- 结果表。
- 空结果提示。

结果表列为：

- `中文名`
- `繁中名`
- `英文原名`
- `CP`
- `相对强度`
- `地点/来源`
- `译名状态`

血量、伤害、防御、保护、经验和金币不在第一版结果表展示。移动端布局改为上下排列：筛选条件、强度区间、结果表。

## 错误处理

- 当前角色战力为 `0` 或无效时，不计算强度，提示用户先完善角色数据或填写手动战力。
- 手动覆盖战力必须是大于 `0` 的数字；非法值不保存、不筛选，并显示提示。
- 怪物 CP 缺失或无法解析时，该记录不参与运行筛选。
- 版本未知、译名缺失、活动怪物都不是错误，通过筛选状态和标签呈现。
- “全部已知数据”范围需要提示包含未校对译名、版本未知或后期记录。

## 测试策略

领域逻辑测试覆盖：

- 强度分档边界：`0.8`、`1`、`1.4`、`2`、`3`。
- 角色战力与手动覆盖战力的优先级。
- 默认过滤 G13 及以前、非活动、有 CP、版本可确认的怪物。
- 全部已知数据范围。
- 包含版本未知开关。
- 名称搜索匹配简体、繁中、英文。
- 地点搜索。
- 译名状态筛选。

界面行为测试覆盖：

- 页签切换不丢失当前角色数据。
- 当前角色总战力变化后，怪物页签使用的新战力同步更新。
- 手动覆盖战力只影响筛选，不修改角色档案。
- 空结果提示。
- 非法手动战力提示。

## 数据刷新流程

怪物 CP 数据通过 `tools/buildMonsterData.py` 刷新。该脚本使用 Python 标准库读取 Mabinogi World Wiki 的 `List of Monster CP` 页面，写入 `data/raw/mabinogi-world-monster-cp.json`，并生成浏览器使用的 `src/monsters/monsterRecords.js`。

刷新命令：

```powershell
python "tools/buildMonsterData.py"
```

刷新后需要检查默认 G13 结果、译名状态和版本未知比例，确认没有明显解析错误后再提交。

## 已确认决策

- 使用方案 A 的页签体验。
- 仓库保留完整已知怪物 CP 数据。
- 页面默认显示 G13 及以前怪物。
- 默认使用当前角色战力，同时支持手动覆盖。
- 结果表只显示筛选所需字段，不展示完整怪物属性。
- 版本未知记录默认不显示，但可通过开关包含。
