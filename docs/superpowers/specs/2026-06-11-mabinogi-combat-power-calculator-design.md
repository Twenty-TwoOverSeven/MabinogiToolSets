# 洛奇战斗力计算器设计

## 概要

构建一个本地静态网页形式的洛奇战斗力计算器。第一版覆盖 G13 及以前的技能，界面使用中国大陆简体中文译名。用户可以维护多个角色档案，输入白值属性和已学技能等级，计算当前总战斗力，并通过 JSON 导入导出长期保存数据。

参考资料为台湾版页面 `https://mabinogi.fws.tw/skills_combat_power.php`。该页面的技能战斗力表可作为数据来源，但应用需要排除 G13 之后的技能，并使用由用户提供或校对的大陆简体译名。

## 目标

- 提供一个无需后端的本地浏览器计算器。
- 支持多个角色档案。
- 保存角色名、种族、称号、八项白值属性和已学技能等级。
- 按用户确认的公式计算总战斗力。
- 以 JSON 导入导出作为可靠持久化方式。
- UI 使用大陆简体译名，同时保留台湾源名称用于搜索和数据维护。
- 在技能列表中高亮当前贡献最高和次高的技能行。

## 非目标

- 第一版不覆盖 G13 之后的技能。
- 不把浏览器本地存储当成唯一可靠存档。
- 不做账号登录、云同步或后端数据库。
- 不自动导入游戏内角色数据。
- 不把台湾译名作为主要 UI 术语。

## 应用形态

第一版是一个可在本地浏览器运行的小型静态 Web 应用。浏览器本地存储只用于自动保存当前工作状态，正式备份和迁移依赖导出的 JSON 文件，因为用户会经常清理浏览器数据。

应用分为三层：

- 技能数据层：静态技能元数据和战斗力表。
- 角色档案层：可编辑的角色状态和导入导出 schema。
- 计算层：独立于 UI 的纯计算函数。

这种分层可以让公式测试更直接，也能在修正技能译名或技能战斗力数据时不破坏旧角色存档。

## 技能数据模型

每个技能记录包含：

- `id`：稳定的内部标识，用于角色存档引用。
- `zhCNName`：大陆简体中文显示名。
- `twName`：参考页面中的台湾名称。
- `category`：技能分类，用于数据组织和可选筛选。
- `introducedBy`：版本标记，用于过滤到 G13 及以前。
- `combatPowerByRank`：等级到战斗力的映射。

支持的技能等级为：

```text
练习, F, E, D, C, B, A, 9, 8, 7, 6, 5, 4, 3, 2, 1
```

台湾名称到大陆简体译名的映射由用户提供或校对。角色档案只保存 `skillId` 和 `rank`，不保存显示名或战斗力数值。这样以后修正译名或技能表时，旧存档会自动使用更新后的数据。

未添加到角色的技能视为未学，不参与计算。

## 角色档案模型

每个角色档案保存：

- `id`：稳定的角色档案标识。
- `name`：角色名。
- `race`：种族，可选人类、精灵、巨人。
- `title`：称号，自由文本，仅用于辨认。
- `stats`：生命力、魔法值、体力值、力量、智力、敏捷、意志、幸运。
- `skills`：已学技能列表，每项为 `skillId + rank`。

种族和称号只用于区分角色，第一版不参与战斗力计算。

## 战斗力公式

使用用户确认的公式：

```text
总战斗力 =
技能提供的最高战斗力
+ 0.5 × 技能提供的次高战斗力
+ 0.5 × 白值生命力
+ 0.33 × 白值魔法
+ 0.33 × 白值体力值
+ 1.0 × 白值力量
+ 0.2 × 白值智力
+ 0.1 × 白值敏捷
+ 0.5 × 白值意志
+ 0.1 × 白值幸运
```

计算规则：

- 没有已学技能时，最高和次高技能战斗力都按 0 处理。
- 只有一个已学技能时，次高技能战斗力按 0 处理。
- 多个技能战斗力相同时，按稳定列表顺序选出最高和次高，避免高亮在界面上跳动。
- 内部计算保留原始数字精度，界面默认显示 2 位小数。

计算结果包含：

- 总战斗力。
- 最高贡献技能及其战斗力。
- 次高贡献技能及其战斗力。
- 技能贡献合计。
- 白值贡献合计。
- 八项白值的贡献明细。

## 用户界面

界面分为四个主要区域。

### 角色档案区

角色档案区支持创建、选择、重命名、复制和删除角色档案。可见信息包括角色名、种族和称号。

### 白值属性区

白值属性区接受非负数字输入：

- 生命力。
- 魔法值。
- 体力值。
- 力量。
- 智力。
- 敏捷。
- 意志。
- 幸运。

字段修改后立即重新计算。每个字段旁可以显示该属性的当前贡献值，方便核对公式。

### 技能区

技能区采用搜索添加模式：

- 用户可以按大陆简体名或台湾源名称搜索技能。
- 选中技能后添加到当前角色。
- 已添加技能显示为列表行，包含技能名、等级下拉框、当前技能战斗力和移除操作。
- 等级下拉框只包含 `练习` 到 `1`。
- 未添加技能视为未学，不显示也不参与计算。
- 当前贡献最高和次高的技能行只做高亮，不显示“最高”或“次高”标签。

### 结果区

结果区实时更新，显示：

- 总战斗力。
- 最高贡献技能名称和数值。
- 次高贡献技能名称和数值。
- 技能贡献合计。
- 白值贡献合计。
- 八项白值贡献明细。

## 导入导出

导出的 JSON 包含：

- schema 版本。
- 导出时间。
- 全部角色档案。

导出数据不复制技能战斗力数值，只引用技能 ID 和等级。这样技能表修正后，旧存档可以使用新数据重新计算。

导入 JSON 时先校验，校验通过前不修改当前数据：

- schema 版本受支持。
- 角色列表存在且结构合法。
- 白值属性为非负数字。
- 技能等级合法。
- 技能 ID 存在，或能被明确报告为未知技能。

导入支持两种模式：

- 替换当前全部档案。
- 合并导入档案。

合并时如果遇到同名角色，导入角色自动追加数字后缀，避免覆盖现有档案。

如果角色引用了未知技能 ID，可以保留角色并报告这些未知技能，供用户后续处理。JSON 格式错误、schema 不支持或结构不合法时，导入失败且不改变当前档案。

## 持久化

浏览器本地存储只作为便利性的自动保存层。应用需要把“导出 JSON 备份”放在清晰位置，避免让用户误以为浏览器数据是长期可靠存档。

## 错误处理

- 非法数字输入需要拒绝或清晰标记，避免静默产生错误结果。
- 空白属性输入只有在界面明确提示时才按 0 处理。
- 导入时遇到未知技能 ID，需要显示足够信息帮助用户修复数据。
- JSON 格式错误或 schema 版本不支持时，显示明确错误并保持当前档案不变。
- 删除包含用户输入数据的角色档案前需要确认。

## 测试策略

公式测试覆盖：

- 无技能。
- 单技能。
- 双技能。
- 多技能。
- 技能战斗力同分。
- 白值贡献产生小数。

导入导出测试覆盖：

- 合法导出后重新导入。
- 不支持的 schema 版本。
- 非法技能等级。
- 负数或非数字白值。
- 未知技能 ID。
- 合并导入时的同名角色。

界面行为测试覆盖：

- 创建和切换角色。
- 修改白值后结果实时更新。
- 搜索并添加技能。
- 修改技能等级。
- 移除技能。
- 高亮最高和次高技能行。
- 替换导入和合并导入。

## 已确认约束

- 当前项目目录不是 Git 仓库，因此规格文档已写入文件，但无法按流程创建 Git 提交。需要初始化 Git 或移动到 Git 仓库后才能提交。
- 大陆简体技能译名映射由用户提供或校对；实现时应让这份数据易于编辑和补全。
